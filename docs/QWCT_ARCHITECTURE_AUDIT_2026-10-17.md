# QWCT architecture audit 2026-10-17 — stop building, fix the real bottlenecks

**Scope:** `main` commit `9bbf8f69de433d4dff0c4042213cd143ecd61737`, 24-file built LEAN Free bundle, current draft PR #57. Read-only code tracing and locally reproduced pure-Python predicates, **NOT** a native LEAN Cloud runtime or profit/author audit. Preserve `NO_ORDERS` and all canonical thresholds.

**Verdict:** The software has many tested components, but the ***single accepted-setup acceptance path is not complete***. There is no justification to replace LEAN, build a second strategy or turn on execution. Many downstream tests can never see a candidate because choices/reconciliations block it upstream.

## P2. Complexity to stop expanding

- The current production Free algorithm package contains **24 Python files, ~6,483 lines, 304 KB** (baseline artifact). Three large source modules are `patterns_bsu.py` (~725 lines), `indicators.py` (~581 lines), and `main.py` (~570 lines).
- The project has separate `BsuDetector`, `M5BsuSequenceScanner`, `BreakoutRetestObserver`, `NativeSecondTvxWindow`, `M5TenReactionObserver` and multiple Research notebooks. Not all are redundant: they represent different evidence scopes. **Do not merge solely to reduce file count.** Instead draw a responsibility map and select one canonical setup pathway.
- `_m5_checks`, `_gate_failures`, overlapping reaction counts and raw BSU events are **bar/event counts**, not unique independent symbol/session/pivot examples. The acceptance report must separate them.
- The repeated versions 5.10/5.11/5.12/5.13 should be frozen as research history, not repeatedly pasted into the core Cloud project. Use the native pipeline as source of truth.

## Existing LEAN features we should REUSE, not rebuild

Official [time-period consolidators](https://www.quantconnect.com/docs/v2/writing-algorithms/consolidating-data/consolidator-types/time-period-consolidators), [native SCALED_RAW for warming RAW subscriptions](https://www.quantconnect.com/docs/v2/writing-algorithms/securities/asset-classes/us-equity/requesting-data), [PPHL pivot comparator](https://www.quantconnect.com/docs/v2/writing-algorithms/indicators/supported-indicators/pivot-points-high-low) and native `OnData`, `OrderTicket`, `Portfolio` / `OnOrderEvent` for the *later* execution stage. Existing main uses LEAN consolidators and daily ATR/SMA correctly in source. PPHL is a comparator, **not** an equivalently labeled Gerchik BSU. No synthetic OHLC, custom broker, OMS, OCO or arbitrary external strategy port.
