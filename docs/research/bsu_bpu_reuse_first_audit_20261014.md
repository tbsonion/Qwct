# Qwct — BSU/BPU: независимое reuse-first исследование готовых решений

**Дата:** 2026-10-14. **Стадия:** аналитика, **НЕ** изменение алгоритма. **Статус:** RESEARCH ONLY, ALL ORDERS DISABLED. Основано на реальных логах LEAN 2.5.0.0.18179 за три последовательных исторических окна и просмотре `strategy/levels.py`, `strategy/scenarios.py`, `strategy/patterns_bsu.py`, `research/bsu_cloud/main.py`, `strategy/config.py`, `docs/strategy_spec.md` в `main`.

## Краткий ответ

**Нет необходимости писать новую торговую платформу или переносить стратегию.** В QuantConnect LEAN уже есть точные штатные компоненты для отсутствующих инфраструктурных частей: `Universe.Top(n)`, Fundamental Universe/Indicator Universe, `PivotPointsHighLow`, `ZigZag`, `History[TradeBar]`, RAW и SCALED_RAW нормализация, нативный `Consolidate`, `Resolution.SECOND` и `TICK`. В Qwct уже есть `levels_for_session`, `BsuDetector` и валидатор нативного M5. Внешние Finviz и TC2000 EasyScan пригодны как **готовые вспомогательные скринеры / визуальная ручная разметка**, но сами по себе не подтверждают точный Gerchik BPU и TVX.

После целевого поиска открытых репозиториев по Gerchik/БСУ/БПУ1/БПУ2 **не найден достоверно проверенный drop-in готовый алгоритм**, совместимый с Qwct LEAN и подтверждённый на настоящем native Cloud. Это *результат выполненного поиска*, а не доказательство отсутствия такого проекта в мире. Компоненты LEAN проверены по документации, но `PPHL`/`ZigZag` не эквивалентны вручную нарисованным линиям Герчика и требуют causal as-of проверки.

## Что конкретно было найдено готовым (проверяемые источники)

1. **QuantConnect Universe.Top(50)** — встроенный daily top-dollar-volume universe; [Liquidity Universes](https://www.quantconnect.com/docs/v2/writing-algorithms/universes/equity/liquidity-universes). Для дополнительной цены/объёма и PIT отбора — [Fundamental Universes](https://www.quantconnect.com/docs/v2/writing-algorithms/universes/equity/fundamental-universes). Нельзя бездумно подписываться на тысячи тикеров — лимиты памяти Free и обычная цена подписок.
2. **QuantConnect PivotPointsHighLow** — штатный `pphl`; [официальные примеры](https://www.quantconnect.com/docs/v2/writing-algorithms/indicators/supported-indicators/pivot-points-high-low). **ZigZag** — [официальный индикатор](https://www.quantconnect.com/docs/v2/writing-algorithms/indicators/supported-indicators/zig-zag). Ни один из них **не детектирует канонический БПУ2 или -30s TVX целиком**; pivot confirmation/repainting — предмет теста.
3. **LEAN Consolidate** — штатные, уже используемые 5-минутные свечи [официально](https://www.quantconnect.com/docs/v2/writing-algorithms/consolidating-data/consolidator-types/time-period-consolidators); **Equity second/tick formats** — [официально](https://www.quantconnect.com/docs/v2/writing-algorithms/securities/asset-classes/us-equity/requesting-data).
4. **LEAN RAW / SCALED_RAW** — [документация](https://www.quantconnect.com/docs/v2/writing-algorithms/securities/asset-classes/us-equity/requesting-data), [реальный официальный пример on-split rewarm](https://www.quantconnect.com/docs/v2/writing-algorithms/securities/asset-classes/us-equity/corporate-actions).
5. **Finviz Screener** — [цена/средний и текущий объём/ATR/относительный объём](https://finviz.com/help/screener), не native LEAN и не завершённый Gerchik detector.
6. **TC2000 EasyScan, Flex Conditions, PCF** — [condition & formula reference](https://help.tc2000.com/m/69401/l/747245-how-to-understand-commonly-used-terms); их скринер и изображения можно использовать для *ручной независимой разметки*, а не как подтверждение исторически причинного LEAN исполнения.

## Первичные источники правил Герчика, найденные при исследовании

- [«БСУ и БПУ» — официальный сайт Герчика](https://gerchik.com/torgovye-patterny/bsu-bpu-teoriya): БСУ — исторический бар слева; БПУ1 — **точно попадает в БСУ**, не обязательно соседний; БПУ2 — **сразу за БПУ1**, в одной плоскости, люфт 20% SL, не должен пробивать экстремум БПУ1; ТВХ — за 30 секунд до закрытия БПУ2. **Нигде в этой конкретной статье** не требуется два предварительно подтверждённых D1 swing экстремума до БПУ1.
- [«Торговый алгоритм Александра Герчика» — официальный сайт](https://gerchik.com/journal/fondovye-rynki/torgovyj-algoritm-aleksandra-gerchika/): в качестве реального рабочего процесса описаны предварительный массовый Finviz отбор, **15–30** акций для наблюдения, D1 + M5, временной план. Утверждение «12:00–13:30 стоит торговать только отбои» поддерживает ограничение *других моделей в это время*, но не доказывает запрет *всех отбоев вне этого времени*. Другая статья/конспект могут вводить более жёсткое правило — до ревизии курса его не менять.
- [SEC FAQ Rule 612](https://www.sec.gov/divisions/marketreg/subpenny612faq.htm), Question 13: subpenny trade **executions** могут быть допустимы, даже когда subpenny quotation/order limits действуют. Не округлять `180.145` до `180.14` без проверки происхождения.

## План без rabbit hole — до следующего кода

1. **Сначала только обзор 3–5 проверочных архивных примеров.** Для каждого: выбранный D1 BSU origin, дата доступности, диапазон swing/cluster, реальные минутные экстремумы, соседние BPU1/BPU2 и timestamp (chart). Первые 3 случая уже есть в логах; найти 2–3 **независимых** обучающих примера, которые **по правилам должны пройти**, иначе нельзя оценить полноту.
2. **Составить таблицу причин пропуска**, не меняя gates: не в universe → уровень не построен → построен, но нет близости → M5 нет exact → BPU2 invalid → session window → SEC/TVX unknown. Подсчёт в **unique symbol/day/origin** и отдельно raw events.
3. **Выбор одного готового пути:** если доминирует coverage — использовать **уже готовый native Qwct screener** в отдельном исследовании / **Universe.Top(50)**; если уровни — сравнить **native PPHL** с существующими swings; если часы — отдельно validate interpretation; если SEC — использовать уже готовый built-in second feed. **Не делать все четыре одновременно**.
4. До окончания этой проверки **не вносить изменения в `Qwct-LEAN-Test`, не изменять пороги Герчика и не включать реальные/бумажные ордера**.

## Границы уверенности

- **Доказано native logs** только количество наблюдавшихся событий на трёх символах и фактические OHLC; это не оценка частоты на всём рынке.
- **Доказано официальными источниками** наличие штатных LEAN primitives и буквальные правила БСУ/БПУ2; это не тождество автоиндикатора ручной разметке.
- **Гипотеза, не доказанный баг:** `swing_k=3 + min_touches=2`, выбор `first_idx`, жёсткое окно и fixed 3-stock universe могут приводить к пропускам. Их эффект не измерен на независимых метках.
- **Нет evidence** для доходности, 3R/4R исполнения, slippage, intrabar -30s наблюдений и реальной broker order behavior.
