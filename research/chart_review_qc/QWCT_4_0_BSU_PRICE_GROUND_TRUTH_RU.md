# QWCT 4.0 — поиск цены BSU и проверка по авторской разметке

**Режим: только исследование D1; никаких торговых сигналов и новых ордеров.**

## 1. Что установлено из первоисточников

1. В [публикации Gerchik Trading Ecosystem «БСУ и БПУ», 09.05.2024](https://gerchik.com/torgovye-patterny/bsu-bpu-teoriya): БСУ — исторический бар, сформировавший уровень; БПУ1 — первый подтверждающий бар **на точной цене БСУ**, необязательно следующий сразу; БПУ2 следует непосредственно за БПУ1, допускается указанный люфт 20% от Stop Loss, но **перебивать цену БПУ1 нельзя**. Вход и риск — отдельные решения. **Нельзя** заменять точную цену BSU медианой соседних swing или выбирать BSU по доходности будущих сделок.
2. [Gerchik Trading Ecosystem, «Хватит путаться в уровнях!», 10.04.2025](https://gerchik.com/journal/instrukczii/xvatit-putatsya-v-urovnyax/): широкие уровни бывают **зонами**, встречаются плавающие уровни и «зеркала», значение имеют реакции и таймфрейм. Это не означает, что любая цена внутри зоны является правильной фиксированной BSU для частной модели BSU/BPU.
3. [«Торговля акциями внутри дня», с. 6–8](https://gerchik.co/docs/TORGOVLYA_AKTSIYAMI.pdf): формирование уровня бывает через экстремумы, изменения структуры, необычные бары, проторговку и гэпы; без конкретной авторской разметки нельзя вывести единую обязательную математическую цену BSU для всех таких случаев.

**Инженерное решение:** не выбирать «победителя» автоматически там, где источник не задаёт универсального селектора. Создать список воспроизводимых **гипотез-кандидатов по фактическим RAW OHLC**, с указанием **исходного бара и даты, когда кандидат впервые был известен алгоритму**, и сравнивать с настоящими авторскими эталонами.

## 2. Реализованные источники кандидатов (все research-only)

| Источник | Цена | Когда известно | Примечание |
|---|---|---|---|
| CONFIRMED_SWING | **High/Low исходной свечи** | Только после `swing_k` подтверждающих закрытых баров | Не медиана кластера |
| CONSOLIDATION_EDGE | **High/Low свечи-экстремума** законченного окна D1 | По закрытии окна | Ширина <= 1.6 native ATR: **эвристика QWCT**, не авторский порог |
| EXPANSION_EDGE | **High/Low необычно широкого бара** | По закрытии бара | Range >= 1.5 native ATR: **эвристика**, не критерий авторского БСУ |
| GAP_OPEN | **Open реального дня с гэпом** | По закрытии этого D1 (консервативно) | Разрыв >= 0.25 native **предыдущего** D1 ATR: **эвристика**, не авторский БСУ |

Детектор сохраняет исходную RAW цену и **никогда** не вычисляет BSU как ATR-медиану цен; может существовать несколько взаимоисключающих кандидатов. Повторы одинаковых исторических источников дедуплицируются без датирования будущим. Обнаружение новой цены не переставляет старый уровень в прошлое. Трендовый излом и сложные ложные пробои остаются **неоднозначными**, не объявляем реализованными правилами автора.

## 3. Проверка точных касаний и проблема исторической сетки

- Для исторических цен на **текущей** биржевой сетке отображается число совпадений **дневных** High/Low исходного направления **после появления кандидата**. Это **не есть БПУ1**: официальный БПУ1 определяется в контексте конкретной модели и короткого TF; на D1 невозможно объявить его подтверждённым без проверки на правильном TF.
- Если RAW историческая цена `OFF_CURRENT_GRID` (например, `AMAT 214.255`), состояние `HISTORICAL_GRID_UNKNOWN`. **Ноль совпадений не значит, что уровень ложный**: требуется исследование источника цены, дробления и исторической tick-grid.
- Для сравнения с другой датой/таймфреймом (например, Brent H4/D1 против AMAT 2024-06-03) есть **жёсткая несовместимость**: такие примеры полезны для иллюстрации типа реакции, но **не** являются ground truth цены BSU для американских акций.

## 4. Аннотированные графики: строгий протокол

Для каждого независимого официально размеченного автора кейса нужно вручную сохранить:

`ticker`, `timeframe='D1'`, `frozen_session`, `level_price`, **`source_date` (исторический BSU-бар)**, `evidence_url`, `note`, а для сравнения реакции — дополнительно `reaction_kind` (наша явно сопоставленная категория из 10) и `reaction_date` (закрывшийся D1).

- Если нет **цены** или **даты исходного BSU-бара**, `INCOMPLETE_AUTHOR_SOURCE`. Нельзя угадывать дату по близкому экстремуму.
- Если эталон относится к другой акции, дате снимка или таймфрейму — **ошибка проверки**, никакой подмены.
- Совпадение `source_date + RAW price` сравнивается с **зафиксированным** кандидатом. Не объявляется «автор одобрил», пока источник/разметка не проверены человеком.
- Сравнение наблюдаемых событий по `(тип, дата D1)` даёт только **охват положительных меток**, не точность (precision), F1 или прибыльность. Для настоящей precision нужны **также полные размеченные отрицательные примеры**.
- В имеющихся снимках 2024-06-03 для AMAT/NFLX/SRPT/MSFT **нет оригинальной авторской отметки BSU и его source bar**. Следовательно, в QWCT 4.0 `AUTHOR_BSU_MARKUPS={}` и `AUTHOR_REACTION_MARKUPS={}`, честный результат — **`NO_AUTHOR_GROUND_TRUTH`**, а не фиктивные «95% точности».

**Важно:** вручную заполнить labels по произвольному мнению разработчика и считать их «разметкой Герчика» **запрещено**.

## 5. Что останется после CI

**Реализовано:** воспроизводимый генератор 4 видов цены, source provenance, as-of known-on, D1 revisits, принцип нет медиан и фальшивых подтверждений, две функции сравнения с независимыми **когда будут доступны** эталонами, тесты на синтетических барах, одноячеечный вывод по четырём акциям.

**Не доказано и не разрешено:** правильная авторская цена BSU конкретной акции, автоматическая коррекция реального исторического источника, точность 10 реакций по размеченным автором акциям, реализованность BPU1/BPU2 на реальном M5, прибыльность и разрешение торговли.

**Следующая минимальная входная информация:** 3–5 размеченных автором кейсов **с датой, ценой BSU, биржевым символом, D1 snapshot и источником**, плюс если есть — датированные реакции. Лишь затем можно выбрать критерии селектора на train-кейсах и проверить на ранее не виденных кейсах; нельзя переобучаться на одном AMAT.


### Уточнение по итогам ревизии

**Совпадения реакций всегда проверяются по тройке (D1-дата, тип реакции, цена уровня)**. Сравнение только даты/типа даёт ложные совпадения на разных близких линиях. **Цена вне нынешней tick-grid**, будь то исходный BSU или размеченная реакция, получает `HISTORICAL_PRICE_GRID_UNKNOWN`, а не «неправильный уровень». В опубликованной картинке со сторонней ценовой шкалой точные совпадения **невозможно подтвердить автоматически**.
